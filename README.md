# מכתבי פרידה - אתר אישי

אתר סטטי קטן: כל אדם סורק ברקוד/קישור אישי, עובר מיני-משחק אישי, ואז רואה **רק** את המכתב שלו.

## איך זה בנוי

```
docs/                       <- זו התיקייה שמתפרסמת לאתר (אל תשנו את זה)
  index.html                   הדף שכולם רואים
  assets/css/style.css         עיצוב
  assets/js/crypto-utils.js    פונקציות הצפנה/פענוח (AES-GCM, Web Crypto)
  assets/js/render.js          לוגיקת התצוגה המשותפת (מבוא -> משחק -> מכתב)
  assets/js/app.js             שולף את הקובץ המוצפן, מפענח, קורא ל-render.js
  assets/img/                  תמונות שמשמשות משחקים ספציפיים (כמו throw)
  assets/js/games/
    memory.js                  משחק זיכרון (מצא זוגות)
    catch.js                   משחק "תפוס" (תפיסת פריטים נופלים)
    quiz.js                    חידון עם שאלות אמריקאיות
  data/people/
    <מזהה-רנדומלי>.json        קובץ אחד לכל אדם - **מוצפן**, לא קריא בלי המפתח

admin/index.html            <- כלי מקומי: כתיבת מכתבים, הצפנה, יצירת ברקודים. לא מתפרסם לאתר!
admin/preview.html          <- כלי מקומי: תצוגה מקדימה של מכתב לפני הצפנה. גם הוא לא מתפרסם!
person-template.json        <- תבנית להעתקה כשמוסיפים אדם חדש
```

**חשוב:** תיקיית `admin/` (כולל `preview.html`) היא לצפייה/עבודה מקומית שלכם בלבד -
היא **לא** נכנסת לתיקיית `docs/` שמתפרסמת לאתר, ואם תפרסמו לפי ההוראות למטה
(source = `docs/` בלבד) היא פשוט לא תהיה קיימת באתר האמיתי - אף אחד חוץ מכם
לא יכול להגיע אליה, אין שם "רשימת אנשים" חיה בשום גרסה מפורסמת.

כרגע יש 3 דוגמאות בתיקיית `docs/data/people/` - אחת לכל סוג משחק (הקבצים
מוצפנים, אי אפשר לקרוא אותם ישירות - ראו "בדיקה מקומית" למטה איך לפתוח אותם).

## איך זה שומר על פרטיות

לכל אדם מיוצר **מפתח הצפנה אקראי משלו** (256-bit AES-GCM). המכתב שלו (כולל
השם, התוכן, הכל) מוצפן עם המפתח הזה *בדפדפן*, לפני שהקובץ נשמר. המפתח עצמו
**לא** נשמר באתר בכלל - הוא קיים רק בקישור/ברקוד של אותו אדם, אחרי הסימן `#`
(למשל `...?id=abc123#k=xxxxxxx`). לחלק שאחרי `#` בכתובת (fragment) יש תכונה
חשובה: דפדפנים **לעולם לא שולחים אותו לשרת** - הוא לא מגיע ללוגים, לא ל-GitHub,
לשום מקום חוץ מהדפדפן של מי שפתח את הקישור.

המשמעות: גם אם מישהו ידפדף בקבצים של ה-repo (אפילו אם הוא ציבורי), הוא יראה
רק בלוקים מוצפנים חסרי משמעות - לא שמות, לא תוכן. רק מי שיש לו את הקישור/ברקוד
המלא (כולל החלק אחרי ה-#) יכול לפענח ולקרוא את המכתב שלו. אין דרך לנחש מפתח כזה.

## איך מוסיפים אדם חדש

הכל קורה בתוך `admin/index.html` (לחיצה כפולה, נפתח בדפדפן, רץ מקומית אצלכם -
לא צריך שרת, ולא נדרש חיבור אינטרנט בכלל - ספריית ה-QR ארוזה מקומית בתוך
`admin/vendor/`):

1. **חלק 1 - כתיבת מכתב**: ממלאים טופס - שם, משפט פתיחה, בחירת סוג המשחק
   (זיכרון / תפוס / חידון - השדות שמתחת לבחירה מתאימים את עצמם אוטומטית),
   את המכתב עצמו, וחתימה. לוחצים "הוסף לרשימה". חוזרים על זה לכל אדם.
   הרשימה נשמרת אוטומטית בדפדפן (localStorage) כדי שרענון בטעות לא ימחק הכל -
   אבל שום דבר לא מוצפן או מפורסם עד שמגיעים לחלק 3.
2. **חלק 2 - האנשים שנוספו**: רשימה עם "תצוגה מקדימה" / "ערוך" / "מחק" לכל
   אחד. "תצוגה מקדימה" פותחת חלון חדש שמראה בדיוק איך המשחק והמכתב ייראו
   לאדם הזה בפועל - בלי להצפין ובלי לגעת בקבצים של האתר, רק לבדיקה שלכם.
   יש גם תיבת "ייבוא/ייצוא JSON מתקדם" מתחת אם נוח לכם לערוך כמה אנשים בבת
   אחת כטקסט (הפורמט מתואר ב-`person-template.json`).

   **חשוב על שמירה:** הרשימה נשמרת אוטומטית בדפדפן (localStorage) - אם תסגרו
   ותפתחו שוב את `admin/index.html` **מאותו דפדפן ומחשב**, היא תחזור. אבל זו
   לא שמירה אמיתית לקובץ - ניקוי נתוני גלישה, מעבר דפדפן/מחשב, או גלישה
   פרטית יכולים למחוק אותה. לכן יש כפתור "הורד גיבוי לקובץ" - שווה ללחוץ
   עליו מדי פעם ולשמור את הקובץ במקום בטוח; "שחזר מקובץ גיבוי" מחזיר ממנו.
3. **חלק 3 - מכתב משותף לכולם (אופציונלי)**: טקסט אחד שכולם רואים אחרי
   המכתב האישי שלהם - עם כפתור ברור "יש עוד דבר אחד - לכולם" שמופיע בתחתית
   כל מכתב אישי (אם משאירים את זה ריק, הכפתור פשוט לא מופיע ואף אחד לא רואה
   שום דבר נוסף). זה נשמר גם אוטומטית בדפדפן, ונכלל אוטומטית בגיבוי לקובץ.
4. **חלק 4 - הצפנה**: ממלאים את כתובת הבסיס של האתר, לוחצים "הצפן, צור
   ברקודים וקבצים לכולם". לכל אדם מתקבל כרטיס עם:
   - כפתור "הורד JSON מוצפן" - את הקובץ הזה שומרים בתוך `docs/data/people/`
     (השם המוצע כבר תואם למזהה).
   - כפתור "הורד QR PNG" - הברקוד להדפסה.
   - כפתור "העתק קישור" (אם עדיף לשלוח בוואטסאפ במקום ברקוד מודפס).

## סוגי המשחקים ואיך מגדירים אותם (gameConfig)

**משחק זיכרון (`"game": "memory"`)**
```json
{ "pairs": ["🎖️", "☕", "🪖", "🌵", "🎸", "⚽"] }
```
עד 8 סמלים/אימוג'ים - אפשר להחליף לכל דבר שרלוונטי לכם ביחד.

**תפוס (`"game": "catch"`)**
```json
{ "emoji": "❤️", "target": 10, "spawnMs": 650, "fallMs": 3000 }
```
`target` = כמה צריך לתפוס כדי לעבור, `spawnMs` = קצב הופעת פריטים חדשים
(נמוך יותר = מהיר יותר), `fallMs` = כמה זמן לוקח לפריט ליפול.

**חידון (`"game": "quiz"`)**
```json
{
  "questions": [
    { "q": "השאלה שלכם?", "options": ["תשובה א", "תשובה ב"], "correct": 0 }
  ]
}
```
`correct` הוא האינדקס (0 = הראשונה) של התשובה הנכונה.

**התעצמות (`"game": "grow"`)**
```json
{ "target": 20, "label": "תתעצם!", "message": "התעצמת!" }
```
לוחצים על הכפתור שוב ושוב, אימוג'י גדל משלב לשלב (🌱🌿🌳💪) עד ל-`target` לחיצות.

**סלפי / אינפלואנסר (`"game": "selfie"`)**
```json
{ "target": 3, "label": "📸 צלם!", "message": "ויראלי! 🔥" }
```
סמן זז על פס קדימה-אחורה, צריך ללחוץ "צלם" בדיוק כשהוא באזור המסומן. כל
"צילום מוצלח" מזיז את האזור למקום אקראי חדש, עד `target` צילומים מוצלחים.

**ריצה (`"game": "run"`)**
```json
{ "target": 40, "label": "רוץ!", "message": "שיא אישי!" }
```
לוחצים כמה שיותר מהר על הכפתור, רץ 🏃 מתקדם לאורך מסלול עד לדגל, עם מד קצב
חי שמראה כמה מהר לוחצים. `target` = כמה לחיצות ("צעדים") צריך כדי לסיים.

**אמן! (`"game": "amen"`)**
```json
{ "rounds": 5, "label": "אמן!", "message": "אמן אמן! 🙏" }
```
מחכים ש"🙏 ברכה!" תופיע על המסך באקראי, ואז לוחצים "אמן" מהר - מוקדם מדי
או מאוחר מדי לא נספר. `rounds` = כמה פעמים צריך לפגוע בול כדי לסיים.

**טירמיסו (`"game": "tiramisu"`)** - משחק בישול קצר בשלושה שלבים
```json
{ "dips": 2, "whiskTarget": 16, "whiskTimeMs": 4000, "layers": 6, "message": "בתאבון! 🍰" }
```
שלב 1 - טבילת ביסקוויט: סמן זז קדימה-אחורה, צריך ללחוץ "טבול" בדיוק כשהוא
באזור הקפה (`dips` טבילות מוצלחות). שלב 2 - ערבוב קרם: לוחצים כמה שיותר מהר
כדי להגיע ל-`whiskTarget` לחיצות תוך `whiskTimeMs` מילישניות - אם נגמר הזמן
המונה מתאפס ומתחילים שוב (לא חוסם, רק מאריך את המשחק). שלב 3 - בניית שכבות:
כל לחיצה מוסיפה שכבה לכוס (☕🧀🍫 חוזר חלילה) עד `layers` שכבות.

**ספירת קלוריות (`"game": "calories"`)**
```json
{ "target": 12, "badRatio": 0.4, "message": "יום מושלם של תזונה! 🎉" }
```
אוכל נופל מלמעלה - צריך לתפוס רק פריטים בריאים (🥦🍎🥕) ולהתעלם מג'אנק פוד
(🍕🍔🍰) שגם נופל בערבוב. `target` = כמה פריטים בריאים צריך לתפוס, `badRatio`
= כמה מהפריטים שנופלים הם ג'אנק פוד (0 עד 1).

**מצא את הגינג'י (`"game": "redhead"`)**
```json
{ "gridSizes": [9, 16, 25, 36], "message": "נדיר כמו יהלום! 🔴" }
```
רשת של אנשים (🧑🧑‍🦱🧑‍🦳🧑‍🦲) עם גינג'י יחיד (🧑‍🦰) מוסתר בפנים - צריך למצוא
אותו. כל סבב הרשת גדלה (כל מספר ב-`gridSizes` = כמות התאים באותו סבב).

**מפקד מלחמה (`"game": "campaign"`)**
```json
{ "fronts": ["חזית צפון", "חזית מרכז", "חזית דרום"], "durationSec": 20, "message": "המלחמה הוכרעה - ניצחון! 🎖️" }
```
כמה חזיתות בו-זמנית, כל אחת מאבדת עמידות עם הזמן ("🚨 נפרצה!" כשהיא מגיעה
ל-0) - לוחצים "שלח תגבורת" כדי לחזק אותה שוב. חזית שנשארת פרוצה ממשיכה
להאריך את הזמן עד הניצחון, כך שצריך לזוז כל הזמן בין החזיתות. `durationSec`
= כמה שניות "נקיות" (בלי פריצות) צריך כדי לנצח במלחמה.

**כלכלה (`"game": "economy"`)**
```json
{ "cycles": 4, "message": "המשק פורח! 📈" }
```
מחיר זז קדימה-אחורה על פס - צריך ללחוץ "קנה" כשהוא בשפל (משמאל) ואז "מכור"
כשהוא בשיא (מימין), חוזר חלילה. `cycles` = כמה עסקאות קנייה+מכירה מוצלחות
צריך כדי לסיים.

**זריקה על תמונה (`"game": "throw"`)**
```json
{
  "targetImg": "assets/img/daniel.png",
  "projectileImg": "assets/img/popit-yellow.png",
  "target": 10,
  "label": "זרוק!",
  "message": "קלעת ישר בפרצוף! 😂"
}
```
משחק שמשתמש בתמונות אמיתיות במקום אימוג'י - כל לחיצה "זורקת" את
`projectileImg` שעפה ופוגעת ב-`targetImg` (עם רעידה קטנה בפגיעה), עד
`target` זריקות. כדי להשתמש בתמונות שלכם: שמים את קובץ התמונה (PNG/JPG,
שם באנגלית בלי רווחים) בתוך `docs/assets/img/`, ומפנים אליו בנתיב יחסי
כמו `assets/img/השם-שלי.png`. כרגע כבר יש שם `daniel.png` ו-
`popit-yellow.png` בשביל הדוגמה של מיקה.

**חשוב לגבי פרטיות:** בשונה מהמכתב עצמו, קבצי תמונה בתוך `docs/assets/img/`
**לא מוצפנים** - הם קבצים סטטיים רגילים באתר. זה אומר שמי שיודע/ינחש את
הנתיב המדויק (או ידפדף ב-repo אם הוא ציבורי) יוכל לראות את התמונה גם בלי
הקישור האישי של אף אחד. זה כנראה בסדר לתמונה שלכם עצמכם, אבל תחשבו על זה
לפני שמעלים תמונה רגישה יותר של מישהו אחר.

רוצים סוג משחק נוסף? תעתיקו אחד מהקבצים ב-`docs/assets/js/games/`, תשנו את
הלוגיקה כרצונכם, ותוסיפו שורת `<script src="assets/js/games/השם-שלכם.js">`
בשלושה מקומות: `docs/index.html` (האתר עצמו), `admin/preview.html` (כדי
שהתצוגה המקדימה תעבוד), ואם רוצים גם אפשרות בחירה נוחה בטופס - אופציה חדשה
ב-`<select id="gameSelect">` בתוך `admin/index.html`. משתמשים בשם הזה בשדה
`"game"`.

## פרסום האתר

מכיוון שכל מכתב מוצפן מראש בדפדפן (ראו "איך זה שומר על פרטיות" למעלה), גם
פרסום דרך **GitHub Pages עם repo ציבורי** (האופציה החינמית) בטוח מבחינת תוכן -
מי שיסתכל בקבצים יראה רק הצפנה חסרת משמעות, לא שמות ולא מכתבים.

עדיין, כשכבת ביטחון נוספת (לא חובה, אבל נחמד): repo **פרטי** ב-GitHub (חינם)
מחובר ל-[Netlify](https://netlify.com) או [Vercel](https://vercel.com) (גם הם
חינמיים לשימוש אישי) - כך אף אחד לא יראה אפילו כמה אנשים יש ברשימה או מתי
עדכנתם קובץ. הגדירו ב-Netlify/Vercel שה-Publish directory הוא `docs`.

בשני המקרים - **אל תעלו** את תיקיית `admin/` לשירות הפרסום עצמו. ב-Netlify/
Vercel זה קורה אוטומטית כי הם מפרסמים רק את `docs/`; ב-GitHub Pages פשוט
הגדירו את מקור הפרסום כתיקיית `docs/` ולא לכל ה-repo.

## סדר עבודה מומלץ מההתחלה עד הסוף

1. תמלאו רשימת אנשים + טקסט מכתב לכל אחד (אפשר בקובץ Word/Notes משלכם קודם,
   ואז להעתיק לתוך מבנה ה-JSON בכלי ה-admin).
2. תפרסמו את האתר קודם (GitHub Pages או Netlify/Vercel - ראו למעלה) כדי לקבל
   את כתובת הבסיס.
3. פותחים את `admin/index.html`, ממלאים את כתובת הבסיס + רשימת האנשים (JSON),
   לוחצים "הצפן, צור ברקודים וקבצים".
